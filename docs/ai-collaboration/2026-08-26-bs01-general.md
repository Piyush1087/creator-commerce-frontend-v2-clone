# BS-01 — General Settings functional reconciliation

Classification: `FUNCTIONAL_STATE_RECONCILIATION`.
Base: `program/brand-settings-mvp` at
`0355b809a839f62d3484d0b2fcd8c695981d493a`, verified after fetching origin.
Branch: `settings-mvp/bs-01-general`.

The existing General feature component and Aurora primitives remain in place.
Only first name, last name and the operational Organization name belong to form
state. The compatibility `organizationLegalName` payload key represents
Organization.name, not registered legal billing identity or BrandProfile.name.
Every active member may save their own personal name. Only Owner and Finance
Admin receive the Organization field in their save payload; Campaign Manager
personal saves omit it.

Email, primary country, reporting currency, Brand name and website are read-only.
Address and tax controls are removed, with concise Billing ownership context.
The fake personal-image uploader and nonfunctional password section are removed.
No new avatar/password/Billing functionality is introduced. No Settings CSS,
navigation, Auth flow, Team component, invitation client or integration file is
changed. The General page still composes the same BrandTeamSettings with the
same data and action callbacks.

The General tests exercise the real component, hook and API client with synthetic
HTTP responses. They cover load, protected fields, allowed save payload, discard,
failure retention, actor policy, and real Team invitation composition.

```text
npm test -- src/features/settings --maxWorkers=2 --minWorkers=1
npm test -- --maxWorkers=2 --minWorkers=1
npm run build
npm run typecheck
npx eslint src/features/settings/components/brand/brand-general-settings.tsx src/features/settings/components/brand/brand-general-settings.test.ts src/features/settings/contracts/brand-settings.contracts.ts
git diff --check
```

Local browser checks used the real SettingsShell and General component with
synthetic data at 375px, 767px and 1280px. Form stacking, protected controls,
Organization-name save, Team presence and absence of document overflow were checked.
This is component/Settings-shell validation, not a full authenticated-app smoke.
No CSS changes, Stitch, Aurora redesign or BS-10 work are included.

Final results: 48 Settings tests (8 General, 9 Team, 8 acceptance, 23 Instagram),
267 tests across the full 41-file frontend suite, build, typecheck and scoped
lint all passed. Vite emitted its existing large-chunk warning; no bundling
changes are included.

Stage B separates personal and Organization permissions. Campaign Manager may
save first/last name, while the read-only Organization field is omitted from
their PATCH payload. Owner and Finance Admin retain both surfaces. General copy
describes operational Organization identity and directs registered legal entity,
billing address, and tax details to Billing. The same 8 focused General, 48
Settings, and 267 full-suite tests pass with the corrected authority.
